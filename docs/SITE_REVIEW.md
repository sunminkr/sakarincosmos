# 페이지 점검 및 다음 작업

점검 기준: 2026-09-21. 아래는 현재 소스에서 확인한 항목입니다. 실제 운영 자료와 서버 설정은 별도로 검증해야 합니다.

## 이번 변경에서 처리한 항목

- observation의 독립 헤더와 공통 스크립트의 프로필 제거 로직 충돌을 해소했습니다. 기존 `closest('div').remove()`는 observation의 오른쪽 영역 전체를 지우고 있었습니다.
- 모든 페이지에 같은 헤더·푸터·모바일 메뉴를 사용합니다. observation과 장바구니에서도 SNS 및 장바구니 링크가 동일하게 표시됩니다.
- 폴더 이름 추측으로 홈과 장바구니에서 TRANSMISSIONS가 활성화되던 문제를 고쳤습니다. 현재 메뉴에만 `aria-current="page"`를 지정합니다.
- HTML을 루트에 읽기 쉬운 이름으로 옮기고 링크를 수정했습니다. 홈은 `index.html`에서 바로 표시합니다.
- 디자인 토큰, 페이지별 JS/CSS, 공통 UI, 문서를 분리했습니다. 잘못된 HTML 바깥의 스크립트 배치와 중복 폰트 로딩을 정리했습니다.
- 한국어 문서의 `lang`, 제목·설명, 본문 건너뛰기 링크, 모바일 메뉴의 키보드 닫기·초점 복귀를 적용했습니다.
- 이미지의 `data-alt`를 실제 `alt` 속성으로 바꾸고 지연 로딩을 추가했습니다. 대체 텍스트 자체는 기존 영문 문구이므로 번역·편집은 필요합니다.
- 장바구니 저장 형식 검증과 저장소 사용 불가 시의 임시 보관, 다른 탭에서 변경한 개수 갱신을 추가했습니다. 기존 저장 키를 유지해 기존 선택 물품을 보존합니다.
- ko/en/ja 공통 사전, 언어별 경로, 서식 함수와 번역 페이지 공개 조건을 준비했습니다.

## 픽업·모바일 추가 구현

- 공연과 상품을 `data/catalog.json`으로 통합했습니다. 홈·공연 타임라인·물품 선택·일괄 주문에서 같은 일정과 가격·옵션을 사용합니다.
- 서울 날짜 기준 공연일 3일 전까지 예약을 받고 이후 픽업을 마감하며, 개별/일괄 신청 API에서도 거절합니다. 열린 탭의 날짜 변경, 신청 가능한 공연이 없는 경우와 데이터 로딩 실패도 처리합니다.
- 티셔츠의 상품+사이즈별 장바구니, 사이즈 변경·다른 사이즈 추가, 이전 장바구니 이관, 상품별 1–9개 수량 검증과 사이즈별 메일 내역을 구현했습니다. 제출 성공 항목만 차감하고 실패 시에는 보존합니다.
- 개별/일괄 폼의 개인정보 동의 확인, Escape 닫기·초점 복귀·Tab 순환을 적용했습니다.
- 320–1440px에서 전체 페이지의 가로 넘침을 확인했습니다. 모바일 공연 표를 세로 목록으로 바꾸고 제목·필터·장바구니·신청 폼의 줄바꿈과 터치 영역을 조정했습니다.
- 음악은 사용자 결정에 따라 **SoundCloud 임베드**로 구성합니다. 직접 음원 파일 연결은 하지 않습니다.

## 확인한 범위와 한계

정적 내부 경로·앵커·스크립트 문법, 여섯 페이지의 320–1440px 가로 넘침과 메뉴를 검사했습니다. 서버의 서울 자정 마감 경계와 옵션 검증, 상품별 사이즈 이관·수정·분리·메일 본문, 발송 실패 재시도, 열린 창의 마감 갱신과 공연 없음 상태를 확인했습니다. 신청 API와 SMTP는 모의 응답을 사용했으며 실제 메일은 보내지 않았습니다.
