# JavaScript 없이 읽을 수 있는 콘텐츠

세 언어의 실제 `.html` 파일에 공개 콘텐츠를 생성합니다. 크롤러를 구분하지 않고 모든 방문자에게 같은 HTML을 제공합니다.

- 홈: 대표 음악·영상의 제목, 날짜, 설명, 원본 링크, 가까운 공연부터 정렬한 예정 공연, 최근 기록, 밴드 소개.
- Transmissions: SoundCloud·YouTube의 공개 기록 전체와 원본 링크.
- Archive: 활성화된 세 서비스의 기록 전체와 원본 링크.
- Observations: 예정·지난 공연의 날짜, 장소, 공연명과 확인된 시작 시간.
- 전체 페이지: 내부 메뉴와 밴드 소개·Contact 링크를 일반 HTML로 제공.

JavaScript가 동작하면 현재 JSON으로 내용을 갱신하고 플레이어·필터·달력을 추가합니다. 데이터 요청이 실패하면 이미 게시된 텍스트와 링크를 유지하고 최신 데이터를 불러오지 못했다는 안내를 표시합니다. 유효한 빈 목록을 받으면 삭제·비활성화된 콘텐츠가 남지 않도록 비웁니다. 예약 가능 여부는 기존처럼 최신 카탈로그와 서버 검증을 사용합니다. 데이터 요청 실패 시 정적 공연 정보를 예약 데이터로 사용하지 않습니다.

## 수정과 배포

콘텐츠의 원본은 `data/catalog.json`, `data/media.json`, `locales/*.js`입니다. HTML의 `prerender` 주석 사이를 직접 편집하지 않습니다.

```sh
python3 scripts/build_locales.py
python3 scripts/build_locales.py --check
```

생성된 루트·`en/`·`jp/` HTML을 JSON 및 공통 파일과 함께 배포합니다. `--check`는 원본과 생성 파일이 일치하지 않으면 실패하므로 JSON만 바꾼 채 배포하는 실수를 확인할 수 있습니다. 런타임에 Python이나 서버 렌더링은 필요하지 않습니다.

예정/지난 공연 구분과 픽업 링크는 생성 시점의 서울 날짜 기준입니다. 픽업은 공연 3일 전까지 가능하며 공연 2일 전 00:00부터 마감됩니다. JavaScript 없는 페이지도 최신 상태로 유지하려면 예약 마감일과 공연 다음 날에 생성·배포를 실행해야 합니다. JavaScript가 동작하면 열린 탭에서도 마감 상태를 갱신하며, 신청 서버는 항상 제출 시점에 다시 검증합니다. 특정 날짜를 검증할 때는 `--as-of 2026-10-24`처럼 지정합니다.

## 확인

`npm test`는 원본 HTML의 실제 콘텐츠, 번역 생성 상태, 공연일 경계, 숨김·삭제 항목, HTML 이스케이프를 검사합니다. 브라우저에서는 JavaScript를 끈 경우와 JSON 요청을 실패시킨 경우에도 영상 링크·공연 일정·소개·Contact가 남는지 확인합니다. JavaScript가 동작하는 기존 예약·미디어·모바일 검사도 함께 실행합니다.
