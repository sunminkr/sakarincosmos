# 다국어 페이지 작업 안내

## 이번에 준비한 범위

- 기본 언어: `ko`. 기존 본문과 일치하도록 모든 HTML의 `lang`을 수정했습니다.
- 공통 메뉴·접근성 문구·페이지 설명: `locales/ko.js`, `en.js`, `ja.js`에서 관리합니다.
- 경로와 서식: `assets/js/i18n.js`의 `SiteI18n`에서 관리합니다.
- 언어는 문서의 `lang`에서 결정합니다. 쿼리나 브라우저 설정만으로 번역되지 않은 본문의 언어를 바꾸지 않습니다.
- `publishedLocales`는 현재 `['ko']`입니다. 공통 사전만 번역된 상태를 완성된 외국어 페이지로 표시하지 않습니다.
- 본문·공연 설명·상품 옵션·미디어 모달·신청 폼과 서버 오류 문구의 전체 번역은 후속 작업입니다.

## 번역 키 사용

문자열만 들어 있는 요소에 키를 붙입니다. 자식 요소가 있는 제목은 번역할 부분을 별도 `span`으로 나눕니다.

```html
<span data-i18n="observations.description">공연 기록 설명</span>
<button data-i18n-label="menu.open" aria-label="메뉴 열기">…</button>
<input data-i18n-placeholder="form.name" placeholder="성함">
<meta name="description" data-i18n-content="meta.home.description" content="…">
<a data-path="observations" href="observations.html">OBSERVATIONS</a>
```

새 키는 세 사전에 동일하게 추가합니다. `data-i18n`은 `textContent`로 적용하므로 사전 값에는 HTML을 넣지 않습니다. 찾을 수 없는 키는 한국어 사전 → 키 이름 순으로 대체합니다. 미번역 키를 자동으로 영어로 간주하지 않습니다.

```js
SiteI18n.t('cart.label', { count: 3 });
SiteI18n.currency(25000); // 언어별 표기, 실제 통화는 항상 KRW
SiteI18n.date(new Date(), { year: 'numeric', month: 'long', day: 'numeric' });
SiteI18n.href('observations'); // 현재 언어의 동일 페이지 경로
SiteI18n.href('objects', 'ja'); // /ja/objects.html (공개 전까지 파일은 없음)
SiteI18n.apply(container); // 동적으로 추가한 DOM의 문구·링크 갱신
```

경로는 `i18n.js` 파일의 위치를 기준으로 계산하므로 도메인 루트뿐 아니라 하위 디렉터리에 배포할 때도 같은 구조를 사용할 수 있습니다. 본문에서 생성하는 동적 링크도 `SiteI18n.href()`로 전환해야 합니다. 공연 상세의 물품 링크는 `SiteI18n.href()`와 `show` 쿼리를 사용해 현재 언어와 선택한 공연을 유지합니다.

## 영어·일본어 본문 추가 순서

1. 페이지별 고정 문구와 공연·상품 데이터를 구분합니다. 날짜·상품 ID·가격·옵션 코드 등은 공통 데이터, 설명·표시 이름은 언어별 필드로 관리합니다. `data/catalog.json`에 공연·상품 공통 데이터가 통합되어 있으며 이 파일의 표시 이름·설명에 언어별 필드를 추가하면 됩니다.
2. HTML 본문의 번역 훅과 동적 JavaScript 문구를 추가합니다. 신청 폼, 대체 텍스트, 오류·완료 메시지도 포함합니다. 날짜는 `Intl` 서식 기능을 사용하고 공연 분류 기준 시간대는 `Asia/Seoul`로 일관되게 정합니다.
3. `en/`, `ja/` 아래에 루트와 동일한 여섯 HTML 파일을 만들고 각각 `lang="en"`, `lang="ja"`를 설정합니다. `assets/`와 `locales/` 참조는 `../assets/`, `../locales/`로 변경합니다. 언어별 페이지를 자동 생성하는 작은 템플릿 빌드를 도입하면 반복 마크업도 줄일 수 있습니다.
4. 제목, 설명, 이미지 대체 텍스트, 신청 폼까지 각 언어로 검수합니다. 한글 본문을 남긴 채 `lang`만 바꾸지 않습니다. 한국어 고유명사·작품명은 번역 정책을 정해 보존하거나 병기합니다.
5. 공개할 언어의 모든 페이지가 존재할 때 `publishedLocales`에 언어를 추가합니다. 그러면 공통 헤더에 언어 링크가 나타나며 현재 페이지와 URL 해시를 유지합니다. 메뉴 공간도 세 언어로 확인합니다.
6. 실제 공개 도메인이 결정되면 각 문서의 self canonical, 언어별 `hreflang`, Open Graph, sitemap을 추가합니다. 존재하지 않는 외국어 URL을 검색엔진에 등록하지 않습니다.
7. 정적 링크 검사 대상에 `en/`, `ja/` 문서를 추가하고, 브라우저 테스트를 실제 번역 페이지 전체로 확장합니다. 현재 브라우저 테스트의 언어 검증은 공통 UI만 대상으로 한 임시 문서 응답입니다.

현재 방문자용 언어 선택은 공개된 페이지 간 링크 방식입니다. 자동 언어 감지나 저장된 설정에 따른 강제 리다이렉트는 도입하지 않았습니다.
