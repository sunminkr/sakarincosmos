# 다국어 페이지 관리

한국어는 루트, 영어는 `en/`, 일본어는 `jp/`에서 제공합니다. 각 언어에 홈·음악·공연·아카이브·굿즈·장바구니의 여섯 페이지가 있습니다. 일본어의 URL 폴더는 `jp`이며 HTML의 `lang`, 번역 사전과 `hreflang`은 언어 코드 `ja`를 사용합니다.

## 소개문과 번역 수정

루트의 여섯 HTML을 공통 원본으로 사용하고, `locales/ko.js`, `locales/en.js`, `locales/ja.js`에서 번역 문구를 관리합니다. `band.name`, `band.tagline`, `band.bio`가 밴드명·캐치프레이즈·소개문입니다. 제공받은 각 언어 소개문을 사용하며 홈과 공통 푸터에 연결되어 있습니다. INFO 메뉴는 홈의 `#about` 소개 영역으로 이동합니다.

메일에 공유할 소개 링크는 한국어 `/#info`, 영어 `/en/#info`, 일본어 `/jp/#info`입니다. 각 홈 HTML에 실제 `info` 앵커가 있어 JavaScript 없이도 소개로 이동합니다. 기존 `#about` 링크도 같은 소개를 가리키며, JavaScript가 동작할 때는 콘텐츠가 늦게 로드되어도 소개 위치를 유지합니다.

본문의 `data-i18n`, `data-i18n-label`, `data-i18n-placeholder`, `data-i18n-content`는 각각 텍스트·접근성 이름·입력 예시·메타 설명을 지정합니다. 자식 태그가 있는 요소는 번역할 텍스트를 별도 `span`으로 감쌉니다. 새 키는 세 사전에 동일하게 추가합니다.

원본 HTML·사전 또는 `data/catalog.json`, `data/media.json`을 수정한 뒤 다음 명령으로 실제 번역 HTML과 정적 콘텐츠를 함께 갱신합니다.

```sh
python3 scripts/build_locales.py
python3 scripts/build_locales.py --check
```

생성된 `en/*.html`, `jp/*.html`도 함께 배포합니다. 페이지를 실행할 때 빌드나 Python은 필요하지 않습니다. 영어·일본어 문서는 JavaScript 실행 전에도 해당 언어로 표시되며, CSS와 스크립트는 공통 파일을 사용합니다. 생성된 파일을 직접 수정하지 마세요.

루트 HTML의 `<!-- prerender:이름:start -->`와 `<!-- prerender:이름:end -->` 사이도 자동 생성 영역입니다. 이 안의 영상·공연 내용을 직접 고치지 말고 JSON 원본을 수정한 뒤 생성 명령을 실행합니다. 공연의 예정/과거 구분은 생성하는 날의 서울 날짜를 기준으로 하므로, 공연일이 지난 뒤에도 다시 생성해 배포합니다. `--as-of YYYY-MM-DD`로 특정 날짜의 결과를 확인할 수 있습니다. 생성된 페이지의 핵심 콘텐츠와 실패 시 동작은 [정적 콘텐츠 안내](PRERENDER.md)를 참고하세요.

## 링크와 데이터

`assets/js/i18n.js`의 `SiteI18n`이 페이지 언어, 링크와 숫자·날짜·원화 표시를 관리합니다.

```js
SiteI18n.t('band.tagline');
SiteI18n.href('objects');           // 현재 언어의 굿즈 페이지
SiteI18n.href('objects', 'ja');     // jp/objects.html
SiteI18n.currency(25000);           // 통화는 모든 언어에서 KRW
SiteI18n.responseMessage(result);   // API 오류 코드를 현재 언어로 표시
```

언어 선택은 현재 페이지, 쿼리의 선택 공연, 앵커를 유지합니다. 브라우저 설정에 따른 강제 리다이렉트는 하지 않습니다. 모바일에는 SNS 아이콘을 상단바에 표시하고 언어 선택을 펼침 메뉴에 배치합니다. 데스크톱에서는 언어 선택도 상단바에 표시합니다.

공연 ID·날짜·가격·옵션은 `data/catalog.json`에서 공유합니다. 장소처럼 번역이 필요한 필드는 각 항목의 `translations.en`, `translations.ja`에서 재정의합니다. 작품명·상품명·SNS 게시물 원문과 외부 서비스 임베드는 원본을 유지합니다. 미디어 데이터도 같은 `translations` 구조를 지원합니다. 영어·일본어용 새 공연이나 상품을 중복 등록하지 않습니다.

장바구니는 같은 브라우저에서 세 언어가 공유합니다. 픽업 가능 여부는 모든 언어에서 서울 날짜를 기준으로 처리하며, 신청 폼·유효성 안내·성공/실패 메시지를 각 언어로 표시합니다. 서버는 기존 메시지와 함께 언어에 독립적인 오류 `code`를 반환합니다. 운영자에게 보내는 신청 메일은 기존 한국어 형식을 유지합니다.

## 검증

`npm test`에서 18개 HTML의 링크와 번역 생성 상태, 모바일 SNS 아이콘, 320–1440px 레이아웃, 언어 전환, 공유 장바구니, 개별·일괄 신청 폼과 오류 번역을 확인합니다. 각 페이지에는 한국어·영어·일본어 상대 URL의 `hreflang` 링크가 포함됩니다. 실제 공개 도메인이 결정되면 절대 URL의 canonical과 공유 메타데이터를 추가할 수 있습니다.
